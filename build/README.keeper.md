# 논제브 로어북 (Lorebook Keeper)

**채팅이 길어지면 앞부분을 AI가 잊어버립니다. 이 확장은 지나간 대화를 날짜별 로어북 항목으로 정리해서, 잊히지 않게 남겨 둡니다.**

SillyTavern 확장이고, 한국어로 만들었습니다.

---

## 왜 필요한가

### 문제 — 대화가 길어지면 앞이 사라집니다

AI에게 대화를 보낼 때 쓸 수 있는 공간은 **책상 한 개** 같습니다. 크기가 정해져 있어서, 새 대화를 올려놓으면 오래된 대화가 책상 끝에서 밀려 떨어집니다.

그래서 200턴쯤 이어간 채팅에서 이런 일이 생깁니다.

- 처음에 정한 호칭을 다시 틀리게 부릅니다
- 이미 죽은 인물이 멀쩡히 등장합니다
- "지난번에 그 얘기 했잖아"가 통하지 않습니다

### 원인 — 떨어진 대화는 어디에도 남지 않습니다

SillyTavern에는 **로어북**이라는 좋은 도구가 이미 있습니다. 항목을 만들어 두면 필요할 때 대화에 끼워 넣어 주는 메모장입니다.

문제는 **그 메모를 사람이 직접 써야 한다**는 점입니다. 200턴을 되짚어 읽으면서 "이건 남겨야 하고 저건 버려도 되고"를 손으로 정리하는 일은, 해 보면 압니다. 거의 아무도 끝까지 못 합니다.

### 해결 — 정리를 AI에게 맡깁니다

버튼 하나를 누르면, 지난 대화를 읽어서 이렇게 정리해 줍니다.

```
### 2026-05-12 — 터커가 파일을 읽다
로리가 숨겨둔 서류를 터커가 찾아냈다. 터커는 그 자리에서 소리 내어 읽었고,
로리는 말리지 않았다. 둘 사이의 신뢰가 처음으로 깨진 장면.
```

날짜와 제목이 붙은 사건 항목이 로어북에 하나씩 쌓입니다. 이게 전부입니다.

여기에 더해, **절대 잊으면 안 되는 것**은 따로 관리합니다.

| 항목 | 내용 | 언제 들어가나 |
|---|---|---|
| ⭐ **코어 규칙** | 호칭, 알아도 되는 것과 모르는 것의 경계, 절대 어기면 안 되는 행동, 숨겨야 하는 정체 | **매 턴 항상** |
| ⭐ **코어 일기** | 지금의 관계 상태, 둘 사이의 역학, 아직 해결되지 않은 것 | **매 턴 항상** |
| 사건 항목 | 날짜별로 일어난 일 | 아래 「발동 방식」에서 고른 대로 |

코어는 확률에 맡기지 않습니다. 검색으로 찾아지길 기다리는 게 아니라 무조건 들어갑니다.

---

## 이런 분에겐 필요 없습니다

솔직하게 먼저 적어 둡니다. 설치하고 실망하시는 것보다 낫습니다.

- **채팅을 짧게 끝내고 새로 시작하는 분** — 밀려 떨어질 앞부분이 애초에 없습니다.
- **로어북을 손으로 쓰는 게 즐거운 분** — 직접 쓴 항목이 항상 더 정확합니다. 이 확장은 그 노동을 없애려는 물건이고, 정확도를 올려 주지는 않습니다.
- **요약을 AI에게 맡기는 게 불편한 분** — 정리 품질은 쓰시는 모델의 요약 실력에 달렸습니다. 사람이 읽고 고쳐야 할 항목이 나옵니다.
- **기억을 자동으로 "골라서" 넣어 주길 원하는 분** — 이 확장은 **고르지 않습니다.** 아래 「하지 않는 일」을 봐 주세요.

---

## 하지 않는 일 — 그리고 그게 의도인 이유

### 외부로 나가는 데이터가 없습니다

이 확장은 **어떤 서버에도 접속하지 않습니다.** 임베딩도, 벡터 검색도, 별도 판정 모델도 쓰지 않습니다. API 키를 넣는 칸이 아예 없습니다.

대화를 요약할 때는 **이미 쓰고 계신 SillyTavern의 연결을 그대로** 씁니다. 즉 이 확장 때문에 새로 생기는 외부 전송은 없습니다.

### 기억을 "골라서" 넣지 않습니다

지금 장면에 딱 맞는 기억만 추려서 넣는 기능은 **없습니다.** 여기서 항목이 들어가는 길은 SillyTavern이 원래 갖고 있는 두 가지뿐입니다.

1. **항상 넣기** (파란불) — 매 턴 무조건
2. **키워드로 넣기** (초록불) — 대화에 그 단어가 나오면

이게 제약인 이유는 분명합니다. 골라 넣으려면 "지금 장면과 비슷한 기억"을 찾아야 하고, 그러려면 항목을 전부 외부 서비스에 보내 숫자로 바꿔 두어야 합니다(임베딩). 그건 위의 "외부로 나가는 데이터가 없다"와 맞바꿔야 하는 일입니다.

**선별 주입이 필요하시면** 자매 확장 [제브 로어북](https://github.com/athenawin00-boop/lorebook-triage)을 쓰세요. 변환 파이프라인은 두 확장이 같은 코드를 공유하므로, 만들어지는 항목의 모양은 완전히 같습니다. 나중에 갈아타셔도 **변환 지점과 되돌리기 기록이 그대로 이어집니다.**

> ⚠️ **두 확장을 동시에 켜지는 마세요.** 둘이 같은 로어북과 같은 변환 이력을 쓰기 때문에 서로의 기록을 덮어씁니다. 하나를 켜려 할 때 다른 하나가 켜져 있으면 확장이 먼저 물어보고, 승인하시면 저쪽을 끄고 이쪽을 켜 드립니다.

### 사용자가 만든 항목은 건드리지 않습니다

직접 넣은 키워드, 직접 설정한 재귀 방지 옵션, 전역 로어북 설정은 **고치지 않습니다.** 이 확장이 손대는 건 자기가 만든 항목까지입니다.

## 설치

### 방법 1 — SillyTavern 안에서 (권장)

1. SillyTavern 우측 상단 **확장(🧩) → Install extension**
2. 아래 주소를 붙여넣고 설치

```
https://github.com/athenawin00-boop/lorebook-keeper
```

3. **페이지를 하드 리프레시** 합니다 — Windows `Ctrl+Shift+R` / Mac `Cmd+Shift+R`

### 방법 2 — 직접 클론

```bash
cd SillyTavern/public/scripts/extensions/third-party
git clone https://github.com/athenawin00-boop/lorebook-keeper
```

⚠️ **폴더 이름을 바꾸지 마세요.** `lorebook-keeper`여야 합니다. 이름이 다르면 설치도 되고 오류도 안 나는데 **설정 창과 패널만 조용히 안 열립니다.** 가장 헷갈리는 고장이라 미리 적어 둡니다.

### 설치가 됐는지 확인하는 법

두 군데를 보시면 됩니다.

1. **확장 목록**에 `논제브 로어북`이 보입니다
2. 채팅창 아래 **요술봉(🪄) 메뉴**에 `논제브 로어북`이 보입니다 — 여기가 패널을 여는 유일한 입구입니다

둘 중 하나라도 안 보이면 하드 리프레시를 한 번 더 해 주세요.

## 처음 쓰는 5분

### 1. 켜기

**확장 → 논제브 로어북 → 켜기**에 체크합니다.

### 2. 로어북 연결 확인

정리한 항목을 **어디에 쌓을지**가 필요합니다. 확장은 순서대로 찾습니다.

1. 지금 채팅에 연결된 로어북
2. 캐릭터 카드에 박힌 로어북

둘 다 없으면 변환할 때 "대상 없음"으로 멈춥니다. 그럴 땐 SillyTavern의 **월드 인포**에서 로어북을 하나 만들어 지금 채팅에 연결해 주세요.

> 전역 로어북과 페르소나 로어북은 **저장처로 쓰지 않습니다.** 전역에 쌓으면 다른 모든 채팅에 이 캐릭터의 사건이 섞여 들어갑니다.

### 3. 요술봉 → 논제브 로어북 → 패널 열기

패널 위쪽에 **챗 적치 막대**가 있습니다.

```
챗 적치                                    전체 59개
████████░░░░░░░░░░░░░▒▒▒▒▒▒▒▒▒▒▒▒▒▒
● ✅ 정리됨 15건  ● ⏳ 대기 24건·12,633tok  ● 🔒 보존 20건·10,795tok
🟡 지금 [챗→로어북 변환]을 누르면 24건·12,633토큰이 넘어가요 — 변환할 만해요
```

- **정리됨** — 이미 로어북으로 넘어간 구간
- **대기** — 지금 누르면 정리될 구간
- **보존** — 최근 몇 개는 손대지 않습니다(기본 20개). 방금 한 대화는 아직 생생해서 요약하면 오히려 손해입니다.

### 4. [챗 → 로어북 변환]

누르면 **발동 방식을 고르는 팝업**이 뜹니다. 아래 절을 봐 주세요.

### 5. 잘 됐는지 확인

- 토스트로 "항목 N건 추가"가 뜹니다
- 패널의 **직전 턴 — 프롬프트에 들어간 것** 표에 ⭐ 코어가 보입니다
- 월드 인포에서 로어북을 열면 `제목 · 날짜` 형식의 항목이 쌓여 있습니다

⚠️ **경고가 함께 뜨면 내용을 확인하세요.** 요약이 중간에서 잘렸을 수 있습니다. 그 경우 아래 「자주 막히는 곳」을 봐 주세요.

## 발동 방식 — 변환할 때마다 고릅니다

변환을 누를 때마다 팝업이 뜹니다. 매번 묻는 건 일부러 그렇게 만들었습니다 — 세 선택지의 **대가가 서로 다르기** 때문입니다. 한 번 고른 값이 조용히 유지되면, 나중에 비용이 왜 늘었는지 알 수 없게 됩니다.

직전에 고른 것이 기본으로 선택돼 있습니다.

### ① 모두 파란불 (상시)

만든 항목 **전부**를 매 턴 넣습니다.

- **좋은 점:** 빠짐없이 기억합니다. 못 찾는 일이 없습니다.
- **대가:** 매 턴 비용이 항목 수만큼 늘어납니다. 팝업에 `선택 시 매 턴 약 +12,633tok` 형태로 **추정치**를 같이 보여 드립니다.
- 막지는 않습니다. 알고 고르시면 됩니다.

> 이 숫자는 대기 구간의 원본 대화 길이로 잡은 추정치입니다. 실제 항목은 요약이라 보통 이보다 **적게** 나옵니다.

### ② 모두 초록불 + AI 키워드 5개

항목마다 키워드를 최대 5개까지 자동으로 답니다. 대화에 그 단어가 나오면 그 항목만 들어갑니다.

- **영어 단어만 답니다.** 한국어는 "바론이" "바론한테"처럼 어미가 붙어서 원형 그대로 걸리는 일이 거의 없습니다. SillyTavern의 단어 단위 매칭 설정이 기본으로 켜져 있어서 더 그렇습니다.
  → **한국어 키워드가 필요하시면 이 옵션은 맞지 않습니다.** ①이나 ③을 쓰시고 키워드는 직접 넣어 주세요.
- **두 단어 이상은 달지 않습니다.** 실제로 `club zion`이라는 키를 가진 항목이 "클럽 zion에 가?"라는 문장에 **걸리지 않는 것**을 확인했습니다. 같은 문장에서 한 단어 이름 키는 걸렸습니다.
- **흔한 단어는 뺍니다** (love, night, he, room, work …). 아무 문장에나 걸리는 키워드는 없는 것보다 나쁩니다.
- **재귀 방지를 항상 켭니다.** 요약 항목의 본문에는 인물·장소 이름이 반복해서 나옵니다. 그 상태로 항목끼리 서로를 깨우기 시작하면 멈추지 않습니다. 실제 로어북 하나(51항목)를 조사했더니 본문이 다른 항목의 키워드를 건드리는 경우가 **221건**이었습니다. 그래서 이 확장이 만든 항목에는 예외 없이 재귀 방지를 걸어 둡니다.

### ③ 모두 초록불 + 키 없음 — 자동 발동 안 됨 (보관·수동 입력용)

항목만 만들어 두고 발동은 시키지 않습니다. 나중에 직접 키워드를 넣거나, 패널에서 파란불로 바꿀 때 씁니다.

### ⭐ 코어는 이 선택과 무관합니다

코어 규칙·일기는 **어느 옵션을 고르든 항상 매 턴 들어갑니다.** "절대 잊으면 안 되는 상태"의 발동 방식을 선택에 맡기면, 그건 더 이상 절대가 아닙니다.

## 패널에서 할 수 있는 일

요술봉 → 논제브 로어북.

### 항목 상태 바꾸기 — 동그라미 한 번

각 항목 옆 동그라미를 누르면 세 상태를 한 방향으로 돕니다.

```
🔵 상시 (매 턴 주입)  →  🟢 키워드 발동  →  ⚫ 꺼짐  →  🔵 …
```

- 확인 팝업은 없습니다. 한 번 더 누르면 계속 돌아가고, 합계 토큰이 즉시 갱신돼서 그게 확인 절차를 대신합니다.
- **⚫ 꺼진 항목도 표에 회색 줄로 남습니다.** 안 남기면 확장 안에서 되살릴 방법이 없어집니다.
- ⚠️ 꺼면 **키워드 발동도 같이 멈춥니다.** SillyTavern이 꺼진 항목을 다른 어떤 검사보다 먼저 걸러내기 때문에 우회할 방법이 없습니다. '꺼짐'은 "이건 당분간 잊어라"라는 뜻입니다.

### 전문 펼치기

`[전문]`을 누르면 그 항목의 본문 전체가 열립니다. 위쪽에 두 가지가 같이 보입니다.

- **발동됨** 배지 — 직전 턴에 이 항목이 실제로 프롬프트에 들어갔다는 표시입니다
- **키워드 칩** — 이 항목에 달린 키워드들

> **어느 키워드가 걸렸는지는 표시하지 않습니다.** SillyTavern이 그 정보를 알려주지 않아서, 표시하려면 저희가 다시 매칭해 봐야 합니다. 그렇게 만든 하이라이트는 실제 판정과 어긋날 수 있습니다. 틀릴 수 있는 표시는 정보가 아니라 거짓말이라서 넣지 않았습니다.

[로어북 매니저](https://github.com/foreverharibo-boop/lore-manager) 확장을 같이 쓰고 계시면, 그 확장이 만든 번역문도 원문 아래에 함께 보여 드립니다(**읽기만** 합니다).

### 직전 변환 되돌리기

변환은 한 번에 다섯 가지를 바꿉니다 — 항목 추가 / 코어 덮어쓰기 / 변환 지점 이동 / 작중 날짜 갱신 / 원본 메시지 숨김.

결과가 마음에 안 들면 **통째로 되돌릴 수 있습니다.** "요약이 잘렸다"도, 그냥 "내용이 별로다"도 정당한 사유입니다. 변환 지점까지 되돌려 주므로 **같은 구간을 다시 변환할 수 있습니다.**

### 기존 항목 스플릿

예전에 손으로 쓴 통짜 로어북 항목을 날짜별 덩어리로 나눠 줍니다. 실행 전에 **로어북을 자동 백업**합니다.

## 자주 막히는 곳

<details>
<summary><b>"대상 로어북이 없어요"라고 나옵니다</b></summary>

지금 채팅에도, 캐릭터 카드에도 로어북이 연결돼 있지 않습니다. 월드 인포에서 로어북을 만들어 이 채팅에 연결해 주세요. 전역·페르소나 로어북은 저장처로 쓰지 않습니다(다른 채팅에 섞입니다).

</details>

<details>
<summary><b>요약이 문장 중간에서 끊겼습니다</b></summary>

응답 최대 토큰이 부족해서 잘린 경우입니다.

**로어북 만들기 설정 → 응답 상한**을 올려 주세요(기본 16,384).

특히 **추론(thinking) 모델**을 쓰시면 생각하는 데 쓰는 토큰이 출력 예산을 먼저 먹습니다. 그래서 같은 설정에서 일반 모델보다 더 심하게 잘립니다. 넉넉하게 잡아 주세요.

경고가 떴더라도 **항목은 저장됩니다.** API 호출 여러 번을 버리는 게 더 나쁘기 때문입니다. 잘린 게 확인되면 [직전 변환 되돌리기]로 지우고 설정을 고쳐 다시 하시면 됩니다.

</details>

<details>
<summary><b>한 번에 너무 많은 대화를 정리하려니 오래 걸립니다</b></summary>

**로어북 만들기 설정 → 슬라이스**가 한 번에 읽는 대화 분량입니다(기본 18,000토큰). 이보다 길면 여러 번에 나눠서 처리합니다. 오래 걸리는 건 정상이고, 중간에 창을 닫지 마세요.

</details>

<details>
<summary><b>비싼 모델로 RP 중인데 정리에도 그 모델이 쓰입니다</b></summary>

**로어북 만들기 설정 → 연결 프로필**에서 정리에만 쓸 싼 모델을 따로 지정할 수 있습니다.

⚠️ 지정한 프로필이 실패하면 **조용히 원래 연결로 넘어가지 않고 오류를 냅니다.** 일부러 그렇게 했습니다 — 조용히 넘어가면 비싼 연결로 배치 작업이 돌아가는데 알 방법이 없습니다.

</details>

<details>
<summary><b>항목 제목에 날짜가 있는데 AI가 시기를 헷갈립니다</b></summary>

로어북 항목의 **제목은 AI에게 전달되지 않습니다.** SillyTavern이 본문만 넣기 때문입니다(제목은 편집창에서 사람이 보는 값입니다).

그래서 이 확장은 날짜를 **본문 맨 앞에** 넣습니다.

```
### 2026-05-12 — 터커가 파일을 읽다
(본문)
```

예전 버전으로 만든 항목에는 이 헤더가 없을 수 있습니다. 채팅을 열 때 확장이 알아서 붙여 드립니다(제목 형식이 이 확장이 만든 모양일 때만 — 손으로 쓰신 항목은 건드리지 않습니다).

</details>

<details>
<summary><b>날짜가 실제 날짜와 다릅니다</b></summary>

일부러 다릅니다. 항목의 날짜는 **작중 시간**입니다. 하루 앉아서 작중 3개월을 쓰실 수도 있으니, "내가 언제 타이핑했는지"는 이야기 속 시간과 아무 관계가 없습니다.

확장은 이 순서로 날짜를 정합니다.

1. 대화에 작중 날짜가 직접 나오면 그걸 씁니다
2. 아니면 "다음 날", "사흘 뒤" 같은 표현으로 계산합니다
3. 둘 다 안 되면 마지막 날짜를 그대로 씁니다

</details>

<details>
<summary><b>제브 로어북과 같이 쓸 수 있나요?</b></summary>

**설치는 둘 다 해 두실 수 있지만, 켜는 건 한 번에 하나입니다.**

둘이 같은 로어북과 **같은 변환 이력**(어디까지 정리했는지, 무엇을 되돌릴 수 있는지)을 공유합니다. 동시에 켜면 서로의 기록을 덮어씁니다.

이력을 공유하는 건 의도된 설계입니다. 덕분에 **갈아타도 처음부터 다시 정리하지 않습니다.** 하나를 켜려 할 때 다른 하나가 켜져 있으면 확장이 먼저 물어보고, 승인하시면 저쪽을 끄고 이쪽을 켜 드립니다. 상대 확장의 화면은 새로고침하면 반영됩니다.

</details>

<details>
<summary><b>그룹 채팅에서 되나요?</b></summary>

채팅에 로어북을 연결하는 방식은 동작합니다. 캐릭터별로 다른 로어북을 쓰는 그룹 채팅은 아직 지원하지 않습니다.

</details>

## 만들어지는 항목의 모양

| 종류 | 제목(comment) | 개수 | 발동 |
|---|---|---|---|
| 사건 | `제목 · 2026-05-12` (같은 날 여럿이면 `#2`, `#3`) | 제한 없음 | 팝업에서 고른 대로 |
| ⭐ 코어 규칙 | `⭐ Core Rules` | 항상 1개 | 매 턴 항상 |
| ⭐ 코어 일기 | `⭐ Core Diary · 시작~종료` | 최대 3개 | 매 턴 항상 |
| 일기 보관분 | `Diary Archive · 시작~종료` | 넘친 만큼 | 키워드 발동만 |

코어 일기는 600토큰을 넘으면 그 시점에 **봉인**되고(`(sealed)` 표시), 다음 변환부터 새 일기가 열립니다. 일기가 3개를 넘으면 가장 오래된 것이 보관분으로 내려가는데, 이때 **아직 해결되지 않은 항목은 코드가 최신 일기로 옮겨 붙입니다.** 모델에게 맡기지 않습니다 — 맡기면 조용히 사라지는 줄이 생깁니다.

일기를 갱신할 때마다 이전에 있던 미해결 항목이 사라지지 않았는지 대조하고, 사라졌으면 경고로 알려 드립니다. **자동으로 되살리지는 않습니다** — 정당하게 해결돼서 빠진 것일 수도 있어서, 판단은 사람이 합니다.

## 설정

**확장 → 논제브 로어북**에는 켜기 스위치와 `로어북 만들기 설정` 버튼만 있습니다. 채팅 중에도 바꾸실 수 있게, 같은 버튼이 패널 위쪽에도 있습니다.

| 설정 | 기본값 | 안 건드리면 |
|---|---|---|
| 연결 프로필 | 현재 연결된 메인 API | RP에 쓰는 모델이 정리에도 쓰입니다 |
| 슬라이스 | 18,000 | 한 번에 이만큼씩 읽습니다 |
| 응답 상한 | 16,384 | 요약 출력 길이 한도입니다 |
| 사건당 토큰 | 500 | 사건 하나의 분량 목표입니다 |
| 스타일 지시문 | 비움 | 기본 문체로 씁니다. 여기에 원하는 문체를 적으실 수 있습니다 |
| 최근 보존 | 20 | 최근 20개는 정리하지 않고 둡니다 |

설정은 확장 폴더가 아니라 SillyTavern 쪽에 저장됩니다. **확장을 지우거나 다시 설치해도 설정은 남습니다.**
